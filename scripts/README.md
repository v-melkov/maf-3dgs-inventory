# Пайплайн учёта МАФ — этапы 01–07

От исходной записи обхода до обученной 3DGS-модели объекта в формате `.ply`.
Продолжение (масштабирование, фильтрация, OBB, карточка, экспорт) —
этапы 08–16, отдельный модуль.

## Структура

```
run.py                     точка входа
config/defaults.yaml       все параметры и пороги проверок
maf_pipeline/
  core.py                  манифест сессии, запуск программ, отчёты, вывод
  env_check.py             проверка окружения
  st01_ingest.py           приём материала, ffprobe, контрольные суммы
  st02_frames.py           извлечение кадров + отбор по резкости + EXIF-время
  st03_coord.py            извлечение координаты из телеметрии файла
  st05_sfm.py              оценка поз камер (COLMAP)
  st06_segment.py          Grounding DINO + SAM 2
  st07_train.py            обучение (LichtFeld Studio)
data/<сессия>/             одна сессия = один обход = один объект
```

Сессия соответствует обходу одного объекта: система координат, масштабный
коэффициент и параметры геопривязки определяются для каждого обхода
независимо. Внутри сессии может быть несколько объектов — целевой МАФ и
линейный эталон, прогоняемый тем же трактом как объект учёта (п. 3.2.4).

## Развёртывание под Windows

**Внешние программы** (все должны быть в `PATH`):

| Программа | Откуда | Замечание |
|---|---|---|
| ffmpeg + ffprobe | gyan.dev / BtbN | оба исполняемых файла обязательны |
| exiftool | exiftool.org | переименуйте `exiftool(-k).exe` → `exiftool.exe` |
| COLMAP | github.com/colmap/colmap | сборка **с CUDA**, иначе признаки считаются на CPU |
| LichtFeld Studio | ваша сборка | путь можно задать в `train.binary` |

**Пакеты Python** (3.11):

```bat
pip install pyyaml numpy opencv-python pillow matplotlib 
pip install sharp-frames
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
pip install transformers
pip install git+https://github.com/facebookresearch/sam2.git
```

Колёса под `cu128` для RTX 5070 обязательны: архитектура Blackwell (sm_120)
в сборках cu121/cu124 отсутствует, и обратного PTX-совместимого пути с более
ранних архитектур нет. Проверка выполняется командой `check-env`: она печатает
перечень архитектур в сборке и делает пробное вычисление на GPU — наличие
устройства само по себе не означает, что в сборке есть код под него.

Веса SAM 2 (`sam2.1_hiera_large.pt`) скачиваются отдельно, путь задаётся в
`segment.sam2_checkpoint`. Веса детектора подтягиваются `transformers`
автоматически при первом запуске.

Детектор берётся из `transformers`, а не из эталонного репозитория
Grounding DINO: реализация в `transformers` не содержит нативных расширений
CUDA, требующих компиляции через MSVC, — это самое хрупкое место установки
под Windows. Модель и лицензия те же.

## Порядок работы

```bat
python run.py check-env --report env_protocol.json

python run.py init data\bench-01 --config config\bench-01.yaml
copy DJI_0001.MP4 data\bench-01\01_raw\

python run.py all data\bench-01 --object target --prompt "wooden bench"
python run.py status data\bench-01
```

Отдельный этап перезапускается по имени: `python run.py sfm data\bench-01 --force`.

Эталон обрабатывается как ещё один объект той же сессии:

```bat
python run.py segment data\bench-01 --object ruler --prompt "surveying staff"
python run.py train   data\bench-01 --object ruler
```

## Что требует проверки на вашей сборке

Три места, где документация инструментов неполна. Все они изолированы и
снабжены внятной диагностикой при несовпадении.

**1. Формат `selected_metadata.json`.** Схема файла, который пишет
sharp-frames, не документирована. `_resolve_selection()` в `st02_frames.py`
разбирает несколько вероятных вариантов, а при неудаче переходит к
сопоставлению по основе имени файла. Если не сработает и это — отказ выведет
фактический перечень ключей JSON, останется дополнить список в функции.

**2. Каталог масок в LichtFeld Studio.** Параметр `--images` задаёт имя
каталога изображений, аналогичного параметра для масок в справке нет.
Набор данных собирается жёсткими ссылками, маски кладутся под двумя
вариантами имени (`frame.png` и `frame.jpg.png`), каталог задаётся
`train.masks_dir_name`. Пересборка под другую схему не требует
переизвлечения кадров.


## Точки контроля

| Этап | Автоматические проверки | Визуальный контроль | Ввод оператора |
|---|---|---|---|
| 01 | длительность, разрешение, частота, VFR, разрывы серии | — | — |
| 02 | число кадров, резкость ниже медианы | контактный лист | — |
| 05 | число подмоделей, доля регистрации, репроекция, длина трека | центры фотографирования | подтверждение при распаде реконструкции |
| 06 | наличие масок, скачки площади, касание границ, доля отбраковки | оверлеи, график площади | выбор объекта из нескольких |
| 07 | видеопамять, число кадров, наличие .ply, число гауссианов | просмотр модели | — |

Четыре обязательные точки визуального контроля и две точки ввода оператора
на пять этапов. Соотношение — количественная характеристика степени
автоматизации для п. 3.5.

## Отчётность

Каждый этап пишет `<этап>_report.json`: статус, длительность, версии
использованных программ, значения всех параметров, числовые показатели,
предупреждения, пути к материалам контроля, контрольные суммы входов.
`session.json` агрегирует состояния этапов.

Сводные таблицы главы 3 собираются из этих отчётов без ручного переноса
цифр. Поля инвентарной карточки (п. 2.6.2) берутся оттуда же:
`n_frames` — из отчёта этапа 02, `n_gaussians` — из этапа 07,
`geo_rmse` и `scale_factor` появятся на этапах 08–10.

Журналы в `logs/` содержат полные командные строки всех вызовов внешних
программ — это делает журнал сессии воспроизводимым протоколом обработки,
пригодным для приложения к работе.
